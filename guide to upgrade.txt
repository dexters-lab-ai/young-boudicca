aiDreams: 3D AI NFT Agent Creator - Technical Plan
Project Overview
The "aiDreams" app will allow users to create unique 3D AI companions by combining custom VRM models (hosted via URL), custom VRMA animations (hosted via URL), and predefined behaviors (environment, look-at controls, gesture/mood triggers). Each created companion will be a unique NFT on the Solana blockchain. Users can subscribe to these agents using a Solana-based token (placeholder: USDC), with subscription fees split between the project and the creator.
The core components and technologies required to achieve the project are as follows:

    Frontend (React App): This will include an agent creation modal/form, agent viewing/interaction interface, a creator dashboard/agent management panel, wallet integration (Solana), NFT display and management, and a subscription button/flow.
    Backend (Node.js/Express with Mongoose/MongoDB Atlas): This will handle API endpoints for agent creation, retrieval, and updates. It will also handle user authentication and authorization, database management (MongoDB Atlas) for agent metadata, creator wallets, subscription tracking, and payout data. In addition, it will include a webhook listener (for Solana transactions, if feasible) or scheduled job (for transaction polling), NFT metadata management, and payout tracking/recording.
    Blockchain (Solana): This component will be responsible for NFT minting and management (using a third-party service or custom program), token gating for subscriptions (checking if a user's wallet has sent the required token), and payment handling (direct creator-to-user token transfer for subscriptions).
    Cloud Storage: This will involve options such as echo3D (recommended), a DIY option using Google Drive with modified public links, and NFT asset storage via IPFS (Pinata or similar).
    AI Integration (Conceptual): This will include LLM integration (OpenAI API, Google Gemini API) for conversational AI and Text-to-Speech (TTS) & Speech-to-Text (STT) for voice interaction.

3. NFT Agent Creation Workflow (Solana)
This workflow is the core "unique point."
Third-Party Solana NFT Service (Recommended):

    Metaplex SDK / Umi: The standard way to create NFTs on Solana. Using the JS SDK can simplify interaction with Solana.
    Key Steps:
        Prepare Metadata:
            Create a JSON file containing the NFT's metadata (following Metaplex standards).
            This metadata will include: name (Agent's Name), symbol (e.g., 'MIKOAI'), description (Agent's Description), image (a static render or short video of the agent), properties (e.g., VRM_URL, Environment_URL, Gestures, Moods, Creator_Wallet).
            Crucial for Uniqueness: Store the vrmModelUrl and vrma URLs directly within the NFT metadata's properties or attributes array. This proves its uniqueness and links directly to the assets.
        Upload Metadata to IPFS: Use Pinata to upload the JSON metadata file to IPFS. This generates a unique IPFS hash (ipfs://...).
        Upload Image/Video to IPFS: The image field in your metadata should point to an IPFS-hosted image or short video showcasing the agent.
        Mint NFT: Use the Metaplex SDK to mint the NFT on Solana. The minting transaction will require the user's wallet (the creator's wallet) to sign and pay a small gas fee.
            The minting process will involve creating the NFT's mint account, the associated token account for the creator, and updating the NFT's metadata with the IPFS URI.
            The agent.creatorWalletAddress from the Agent schema will be the NFT's creator wallet.
    Code Stub (Conceptual - using Umi/Metaplex JS SDK):

javascript

import { createUmi } from '@metaplex-foundation/umi-bundle-defaults';
import { irysUploader } from '@metaplex-foundation/umi-uploader-irys'; // Or use ipfsUploader
import { createNft, TokenStandard, MPL_TOKEN_METADATA_PROGRAM_ID } from '@metaplex-foundation/mpl-token-metadata';
import { publicKey, createSignerFromKeypair, signerIdentity } from '@metaplex-foundation/umi';

// Assume creatorKeypair is loaded from the creator's wallet signature
// Assume agentData contains name, description, vrmModelUrl, creatorWalletAddress, etc.

const mintAgentNFT = async (agentData, creatorKeypair) => {
    const umi = createUmi('YOUR_SOLANA_RPC_URL'); // e.g., 'https://api.devnet.solana.com'
    const signer = createSignerFromKeypair(umi, creatorKeypair); // Or use wallet adapter for browser
    umi.use(signerIdentity(signer));
    umi.use(irysUploader()); // Or other uploader for IPFS

    // 1. Upload image/video (e.g., a render of the VRM model)
    const imageFile = new File(['...'], 'agent_render.png'); // Replace with actual file or dynamically generate
    const [imageUrl] = await umi.uploader.upload([imageFile]);

    // 2. Prepare metadata JSON
    const metadata = {
        name: agentData.name,
        symbol: 'MIKOAI',
        description: agentData.description,
        image: imageUrl,
        animation_url: agentData.vrmModelUrl, // Could also point to VRM model for viewing
        properties: {
            files: [
                { uri: agentData.vrmModelUrl, type: 'model/vrm' },
                // Potentially include VRMA URLs here as well
            ],
            category: 'virtual_companion_nft',
            creatorWallet: agentData.creatorWalletAddress,
            // Add gestureTrigger URLs and other unique properties
            customGestures: agentData.gestureTriggers,
            moodTriggers: agentData.moodTriggers,
            environment: agentData.defaultEnvironmentUrl,
            lookAtEnabled: agentData.lookAtEnabled,
        },
        attributes: [
            { trait_type: 'Type', value: 'AI Companion' },
            { trait_type: 'Uniqueness', value: 'One-of-a-Kind' },
            // ... other attributes
        ]
    };

    // 3. Upload metadata to IPFS
    const [metadataUri] = await umi.uploader.upload([metadata]);
    console.log("Metadata URI:", metadataUri);

    // 4. Mint NFT
    const { signature, mint } = await createNft(umi, {
        mint: generateSigner(umi), // Umi generates new mint account
        name: metadata.name,
        symbol: metadata.symbol,
        uri: metadataUri,
        sellerFeeBasisPoints: 0, // No royalties on primary sale for simplicity, or set your percentage
        creators: [{ address: publicKey(agentData.creatorWalletAddress), share: 100, verified: false }],
        isMutable: true, // Allow metadata updates if needed later
        tokenStandard: TokenStandard.NonFungible,
        // ... other options
    }).sendAndConfirm(umi);

    console.log('Successfully minted NFT!', { mint: mint.publicKey, signature });

    return { mintAddress: mint.publicKey.toString(), metadataUri, transactionHash: signature };
};

4. Subscription Model & Payment (Solana)

    Token Gating / Payment Check:
        Subscription Token: Use a placeholder token like Solana USDC.
        Mechanism: When a user clicks "Subscribe," the app will:
            Present the creator's saved creatorWalletAddress and the required token amount (1 USDC).
            Prompt the user to send 1 USDC to the creatorWalletAddress using their connected wallet (e.g., Phantom).
            After the user signs and sends the transaction, the frontend captures the transaction hash.
            Send the transaction hash and the agent ID to the backend for verification.
        Backend Verification:
            Solana Transaction Listener (Ideal but Complex): Set up a listener that monitors for incoming USDC transfers to the creator's wallet. When a transaction is detected, verify it matches the expected amount, sender (subscriber's wallet), and token.
            Polling (Easier but Slower): Periodically check the transaction history for the creator's wallet on Solana. Look for recent transactions that meet the criteria.
            Hybrid (Recommended for Simplicity): The user provides the transaction hash on the frontend. The backend then immediately verifies that specific transaction:
                Fetch transaction details.
                Verify sender, receiver, amount, and token address.
                Verify timestamp.
        Subscription Activation: If verification passes, update the User document's subscribedAgents array to activate the subscription for the given agent.
        Reward Tracking: Record the subscription details, including the creatorWalletAddress, in a pending payout ledger on the backend. This ledger will track the 75% creator share and 25% project share.
    Fee Split Logic (Backend):
        The 1 USDC goes directly to the creator's wallet.
        Project Buyback/Burn (25%):
            Option A (Creator sends back): The creator would have to manually send 25% of their earnings to the project's wallet.
            Option B (Separate token transfer): When a user subscribes, they send 1 USDC to the creator AND 0.33 USDC to the project's wallet. This means the total subscription fee is 1.33 USDC.
            Option C (Using a Solana Program): A custom Solana program could handle the split directly. The user sends 1 USDC to the program, and the program then automatically distributes 0.75 USDC to the creator and 0.25 USDC to the project's wallet.
        Payout Tracking: The backend will track the totalRevenueEarned for each agent and the amount due to each creator.

Key Challenges & Considerations

    Google Drive Direct Links: Consider providing a very specific helper tool within your app that takes the Google Drive share link and attempts to convert it to a direct link. Or strongly encourage echo3D.
    Solana Transaction Verification: A Solana Program (smart contract) is the most robust way to handle the payment split and subscription logic. Using a Transaction Listener (via WebSockets) is a good middle ground.
    LLM Integration: Integrating an LLM (e.g., Google Gemini) and managing its state for each AI companion will be a separate, significant task. You'll need to store context for each agent to make conversations dynamic.
    Security: Ensure proper sanitization of URLs and other user inputs. Protect creator payout wallets.
    User Experience: Clear instructions, intuitive UI, and smooth wallet integration are critical for non-technical users.
    Scalability: Consider backend service scaling.
    NFT Metadata Updates: Implement a "update NFT metadata" flow, which requires the creator's wallet to sign another transaction. Make isMutable true when minting.

This plan provides a framework for building the project. The next step is to build out the core components, starting with the Agent Creation Modal and backend API endpoints, then integrating with Solana for NFT minting and subscription logic.
